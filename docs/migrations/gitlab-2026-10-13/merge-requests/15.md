Max aka Mosheh (max757) at 2026-10-02T07:25:28.382Z. System event: no. Resolved: True.

[P2] Persist the bond together with freight acceptance

**Location:** `src/vessels/vessels_contracts.c:555` (right, reviewed head `e2008096`).

Save a captain with 1,000 gold, accept ten units of salt (a 140-gold bond), and crash before their next ordinary character save: the contract and ten cargo units are already in MySQL, but the player reloads with all 1,000 gold. `award_gold()` only changes the in-memory balance, and this acceptance path never calls `save_char_checked()`, so the newly introduced bond disappears while the freight remains deliverable or sellable. Conversely, `vessel_db_save_cargo()` silently returns on a write failure, so a later character save can retain the debit without durable freight. Make acceptance a checked, recoverable operation: persist the debit, transactionally update the contract and manifest, and roll back or reconcile all three records on failure before reporting success.

**Validation:** Static tracing and a focused C control-flow probe using the unchanged acceptance function with stubbed game/database interfaces reproduced both outcomes. No full build, live server, or database integration suite was run.

Fixed in `a703572e3` (record `06ec25a35`).

- Acceptance now claims the contract and rewrites the manifest in one transaction. Any failure rolls back and unloads the freight in memory, including a failed manifest write, which `vessel_db_save_cargo()` now reports.
- The bond is debited only after `COMMIT`, then saved with `save_char_checked()`.
- If that save fails, the gold is restored, the contract is reopened (only if still taken by this captain, through a prepared statement) and the freight is unloaded and re-saved. A SYSERR is logged if that compensation itself fails.
- The player sees "no gold was taken" in both failure cases.

`Test_vessel_freight_bond_pays_for_the_goods` (DB-backed) now covers:

- a refused manifest write (a CHECK constraint on the fixture table);
- a failed character save;
- the success path, with the captain saved to a scratch player file.

Each failure leaves gold, contract status and manifest unchanged. The test fails on the previous acceptance code. The local CI matrix passed all 33 jobs on `a703572e3`.
