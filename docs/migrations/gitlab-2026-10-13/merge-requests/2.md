## Description

Implements the Duris player races plan (the plan itself is retired in the last commit; its content now lives in `docs/guides/PLAYER_RACES_REFERENCE.md`).

Closes #2

## What changes

- **Shared mechanics.** `FEAT_LEONINE_FRAME` becomes `FEAT_TAURIC_FRAME` (same ID 1267). New `FEAT_PSIONIC_RESISTANCE` (1322) held by Trelux; the mental-damage case and the Lich cold immunity read their feats beside the race checks saved characters still need. Race grants of epic damage reduction now build the DR entry through `update_feat_damage_reduction()`. `race_is_transformation_only()` is the single hard-lock predicate. `respec_engine()` accepts a NULL argument for every race.
- **Twelve creation races (IDs 152-163):** Centaur, Githzerai, Firbolg, Githyanki, Kobold, Drider, Thri-Kreen, Minotaur, Kuo Toa, Orog, Harpy, Stormkin. Registry data, parser (name and display name), creation help cases, web media keys, XP tiers, hit points, family predicates, lost slots.
- **Five descend forms (IDs 55-59):** Death Knight, Wight, Revenant, Shadow Beast, Phantom. Transformation-only; a standard quest race reward converts through `descend_form_conversions[]` in `src/quest/quest.c`. QEDIT, `wtool`, and `QUEST_FILE_FORMAT.md` accept the IDs. No quest awards a form yet.
- **Help:** `sql/components/help_duris_races_entries.sql` (+ verifier, manifest, `EXTRA_DIST`), PSIONIC-RESISTANCE topic, Thri-Kreen in EPIC-RACES; `help.hlp` is the exact projection of the development help DB.
- **Docs:** race reference, race guide, mechanics reference, limb mechanics.

## Worth a reviewer's attention

These go beyond the plan, each because this work exposed the defect:

- An epic damage reduction DR entry has spell 0, which the player-file DR save skips as a duplicate, so it was never saved (study-taken DR was lost on every reload). `load_char()` now rebuilds it from the feat's real ranks.
- `process_race_level_feats()` read `GET_RACE()` (the disguise race). It now reads `GET_REAL_RACE()`, since these are the first races with grants above level 1.
- Protocol v1 web onboarding lists every race on one page; with 45 races it overflowed the 15000-byte payload. v1 race summaries are now 140 characters (`WEB_ONBOARDING_V1_RACE_SUMMARY_CHARS`); v2 is unchanged.
- The Minotaur help topic updates the retired Dragonlance `minotaur` entry in place (it already owned the MINOTAUR and RACE-MINOTAUR keywords), so nothing is deleted.

## Review fixes (6446f4af8)

- Every race reward now saves once the quest history and next stage are recorded, before a follower's load trigger can run, so a restart cannot reopen a completed conversion quest. The Lich and Vampire rewards had no final save at all.
- Transformation is one-way everywhere: the race-reward preflight, the legacy Lich quest (`hlquest.c`), and the Lich rite refuse a character whose real race is already transformation-only.

## Crash fix found during the live check

`close_socket()` freed the character of any descriptor outside `IS_PLAYING()`. The first-quit "Reason:" survey (`CON_QUIT_REASON`), mail and board composition, and the house and board editors keep a character that is still in the world in such states, so a dropped link there freed a character still on `character_list`: the server then spun at 100% CPU or segfaulted in `perform_dupe_check()` at the next login. A character still on the list now goes linkdead and saves; logging back in reconnects to it. Regression test: `Test_lost_link_at_the_quit_survey_leaves_the_character_linkdead` (it aborts on the old code). Verified live on port 4100: a new account's first quit, link dropped at "Reason:", then a login that reconnects with the server idle.
