## Description

Columns and indexes that exist only in `CREATE TABLE IF NOT EXISTS` statements never reach a
database whose table already exists. A schema audit of dev and production against a fresh install
found three that the code depends on:

- `weather_cache.wind_speed` (read by the cyclone spell): missing on production.
- `player_save_objs.idx_name`: missing on production, so every character object load and delete
  scanned about 508k rows.
- `hint_usage_log` still had the older region-keyed shape on both dev and production, so every
  `log_hint_usage()` insert failed with `Unknown column 'room_vnum'`.

`run_legacy_table_migrations()` adds them as versioned, idempotent migrations 2026092701-03, run on
every boot. A failure is logged and retried at the next boot rather than stopping the server.

Already applied: production (after a full DB backup, no restart) and dev (through startup).

Validation: `make test-all` against an isolated MariaDB (1837 + 32 tests), including the new
`Test_legacy_table_migrations_repair_old_shapes_idempotently`; local `quality-clang-tidy` job.
