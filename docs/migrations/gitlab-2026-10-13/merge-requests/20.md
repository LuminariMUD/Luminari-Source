## Description

S13 of the vessel study: transactions that survive a lost connection.

Closes #13

## Problem

Every database connection reconnects by itself (`MYSQL_OPT_RECONNECT`). When one dropped inside a
transaction, the server rolled the transaction back, one command failed, and the statements after
it ran one by one in autocommit on a new session; a `COMMIT` among them reported success. An
object save left the old rows and the new partial ones together. A `COMMIT` whose reply was lost
was taken for a rollback when it may have committed. Work item #13 lists the sites.

Probing the client library with real drops before planning showed two things the item did not
have: `mysql_ping()` retries by itself and returns success on a new session, and the close of a
prepared statement can be the first command to meet the drop, so no statement fails at all.

## Fix

- **The rule lives in the query layer** (`src/database/mysql.c`), the only place that sends
  commands. A connection that lost its transaction is marked and takes no statement until the
  caller ends the transaction: `ROLLBACK` is sent, a `COMMIT` fails and is answered with a
  `ROLLBACK`, a new `START TRANSACTION` starts clean. Queries, prepared statements, the close of
  one, and pings all mark. The mark is kept on the handle (`MARIADB_OPT_USERDATA`), so it
  survives the reconnect and goes with the handle. No writer has to stop at its first failure.
- **`mysql_commit_transaction()`** tells a confirmed `COMMIT`, a refused one and one without a
  reply apart, and rolls back what is not confirmed. Cargo trades use it (`trade_commit()` is
  gone). After a `COMMIT` without a reply, pet storage and retrieval, a hull's change of owner and
  the end of a vessel event read the database back with a locking read, which waits for the lost
  session to finish.
- **Object and house saves.** The writers report a row that was not written. The save commits the
  rest, keeps `PLR_CRASH` or `ROOM_HOUSE_CRASH` so the next pass saves again, and tells the staff
  whose objects they were. `Crash_save_single()` no longer clears the flag after a failed object
  save. `Crash_idlesave()` commits. An extra description that does not fit a record is left out
  instead of the object (object, sheath and pet writers).
- **`house_data`** loses the unique key on `vnum` that let a house keep one object
  (`master_schema.sql`, `db_init.c`), with boot migration `2026100401`.
- **Smaller sites.** A bounty that cannot be read is not overwritten with the new offense. The
  help writers check inside their transaction that the session still holds the help
  synchronization lock. `hedit` deletes removed keywords.
- **The pool** reconnects a stale handle in place instead of closing the handle `conn` points at.

## Found on the way, fixed here

- `mysql_pool_acquire()` could hold the game while the database was away: it retired a connection
  that failed its check and, with none left and none to open, tried again without end on the
  game's one thread. It now returns no connection, which its caller already handles. Read from
  the code, not seen in production.
- `Crash_cryosave()` stored a frozen character's objects beside the last save's, with no
  transaction. It runs only where rent is not free.
- The rule itself: a caller that failed without ending its transaction would have left the
  connection refusing everyone's statements, and the query that loads a player's objects at login
  stops the server when it fails. All 26 transaction sites end theirs on every path, and the mark
  now lasts one game pulse at most: after that the layer rolls the transaction back itself and
  logs it (`3eab48d60`).
- The test database built from `master_schema.sql` had the `house_data` key: the new house test
  failed on it until the boot migration ran.

## Tests

The connection is really lost: `mysql_test_drop_connection_at()` shuts the socket down at a named
statement, before it is sent or after the server ran it. These tests write the real tables with
test-only rows, since a TEMPORARY table goes with its session.

- `unittests/CuTest/test_database_transactions.c` (new): the rule for a query, a prepared
  statement, a statement close and a ping; the helper's three results; the pool; a crash save and
  a house save lost at a row and retried; a row refused on a good connection; the idle, cryo and
  rent saves; the owner transfer, the event finish and the bounty; the help lock and `hedit`.
- `test_database_persistence.c`: the pet save lost at a row, the keeper's store and retrieve both
  ways, the longest record, the left-out extra description, the migration on the old table shape.
- `test_vessel_rewards.c`: the cargo trade test now loses its connection for real.
