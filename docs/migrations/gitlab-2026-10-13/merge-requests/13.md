## What changes for players

A client with native MSDP (or GMCP, through the standard `MSDP` package) can now REPORT twelve more vessel variables, refreshed every half second while aboard and sent only when they change:

- `SHIP_ID` and `SHIP_TARGET`: the hull's contact ID and the ID of the contact her guns are locked on.
- `SHIP_ARMOR` and `SHIP_INTERNAL`: tables keyed `fore`, `port`, `rear`, and `starboard`, each with `CURRENT` and `MAX`.
- `SHIP_SAIL`, `SHIP_RUDDER`, `SHIP_STAMINA`, each with a `_MAX`, as `shipstatus` shows them.
- `SHIP_WEAPONS`: one table per mounted weapon with `SLOT`, `NAME`, `ARC`, `AMMO`, `READY`, and `DAMAGE`.
- `SHIP_CONTACTS`: the `contacts` list, nearest 20 first, with `ID`, `NAME`, `RANGE`, `BEARING`, and `ARC`.

Ashore every one of them is sent empty or zero, as the nine existing vessel variables already are.

## Code and docs

- `src/net/protocol.h` and `protocol.c` declare the variables; `vessel_msdp_update()` in `src/vessels/vessels_admin.c` fills them.
- Help: the MSDP entry lists the new vessel variables in `help.hlp`. It is not a vessel-component entry, so its body goes into the development database at merge (as HEDIT writes it) before the help sync.
- `VESSEL_SYSTEM.md` documents the full vessel MSDP contract, including the GMCP mapping the protocol layer already provides; `MSDP_VARIABLES.md` now lists the vessel variables.
- New live gate: `scripts/vessels/test_vessel_client_in_game.sh` (tactical harness `--client`, login helper `--vessel-client-check`), a raw native MSDP session at sea.
