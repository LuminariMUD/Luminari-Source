## Description

S12 of the vessel study: owned waypoints and routes.

Closes #11

## Problem

Vessel waypoints and routes recorded no creator, so any captain could delete another captain's
idle waypoint or route. Tracing it found a second hole of the same kind: `addtoroute` let any
captain append a waypoint to any route, and a scheduled hull rebuilds her route from that shared
cache at every departure, so a rival could change a public ferry's course, or disable her schedule
with a waypoint her route check cannot reach.

## Fix

- Schema Phase 24: `creator_id INT UNSIGNED NOT NULL DEFAULT 0` on `ship_waypoints` and
  `ship_routes` (the player's ID; 0 for content and rows made before S12), with rollback and
  verifier SQL, `master_schema.sql`, and the same `ALTER`s at boot in
  `vessel_ownership_ensure_schema()`, which runs before the waypoints and routes load.
- `setwaypoint` and `createroute` record the player (an NPC records 0). `delwaypoint`, `delroute`
  and `addtoroute` allow only the creator or an immortal, before S10's in-use refusals, which stay.
  Using a route stays open to every captain.
- Every route and waypoint command resolves a name to the caller's own row first, so a rival's
  same-named row cannot lock a captain out of their own.
- Rows that predate the column keep creator 0 (nothing records who made them): only the staff
  change them. On the development database all three routes are content on schedules.
- Help (DELWAYPOINT, DELROUTE, ADDTOROUTE) in `help.hlp` and `help_vessel_entries.sql`, three new
  help-verifier patterns, `VESSEL_SYSTEM.md`, the player guide, and the testing docs.

## Tests

- `Test_vessel_waypoints_and_routes_answer_to_their_creator`: a mortal captain is refused another
  captain's and a content waypoint and route, reaches their own same-named route, and an immortal
  is not refused. S10's in-use test now runs as the creator.
- DB-backed `Test_vessel_waypoints_and_routes_record_their_creator`: the boot ensure adds the
  column to a pre-S12 table, the commands record the player, a reload reads the creator back,
  another captain is refused, and the creator deletes both rows.
- The rules gate plays the rule with Kohdee (staff) and Vesselmate (a mortal captain).
