Phase 3 of `docs/ongoing-projects/object-save-fixes-and-arm-pricing.md`. Handed to review at
the tag `object-save-fixes-p3` (`8556f9ca8`): two code commits, each with its test, and the

the plan's record of the review.

## Cause

`free_obj()` sends an object with no prototype through `free_object_strings()`
(`src/olc/genobj.c`), which freed every string the object owns except `arcane_mark`.
`free_object_strings_proto()`, the path of an object with a prototype, has always freed it. So
an unnumbered object lost its mark's memory when it was extracted: the file and player-row
loaders give such an object a mark from its `AMrk` line, and the arcane mark spell gives one to
any object.

## What changes

`79a3c99ed`: `free_object_strings()` frees `arcane_mark`.

Its other callers were checked for a double free. Each frees the object or writes over it
afterwards, and each of those objects owns its mark or has none:

- `add_object()` copies the edited object over the prototype, and `copy_object_main()`
  duplicates the mark.
- The OLC cleanup (`src/olc/oasis.c`) and the iedit commit (`src/olc/oedit.c`) free an edit copy
  whose mark `copy_object()` duplicated. The iedit commit leaked that copy's mark the same way,
  and no longer does.
- The spec test fixture frees a prototype from `parse_object()`, which reads no mark.

The prototype teardown in `destroy_db()`, which #15 names, frees by hand and does not call the
function.

Tests:

- `Test_object_saves_bind_player_house_and_serialized_text` no longer frees its two marks by
  hand before `extract_obj()`. It needs a database, and the memory-check job has none.
- `Test_object_without_a_prototype_frees_its_arcane_mark` needs none: it saves and loads a
  marked object through the file loader, compares the mark and extracts both objects.

`a0757112c`, found while checking those callers: `copy_object()` sent every target through
`free_object_strings_proto()`, which compares the target's strings with its prototype's. For a
target with no prototype that read `obj_proto[-1]`; the iedit commit reaches it with any live
object that has no prototype. It now chooses the free function as `free_obj()` does.
`Test_gameplay_object_editor_copy_frees_an_object_with_no_prototype` copies over such an object
with no prototype table at all.

`8556f9ca8`: the plan's record of the phase.

Review location: src/olc/genobj.c; old line None; new line 578; head 900ac3fb3a611d322337aa2204d7d3beac510224.

**Double free and dangling `char_sdesc` when `iedit` edits a corpse, the live object with no prototype this branch is for.**

`copy_object_strings()` (`src/olc/genobj.c:556-570`) duplicates every string that `free_object_strings()` (`:469-487`) frees except `char_sdesc`. `make_corpse()` sets it (`src/combat/fight.c:2224`), and a corpse is an object with no prototype.

Repro, as an immortal: `iedit corpse`, then `Q`.

1. `iedit_setup_existing()` (`src/olc/oedit.c:4035`): `copy_object(edited, live)` -> `*edited = *live`, so `edited->char_sdesc == live->char_sdesc`.
2. `iedit_commit_existing()` (`oedit.c:3994`): `copy_object(live, edited)` -> this line frees `live->char_sdesc`, then `*live = *edited` writes the freed pointer back into the corpse.
3. `oedit.c:4021`: `free_object_strings(edited)` frees the same block again. The corpse keeps the dangling pointer: read by the vampire-spawn naming at `src/magic/magic.c:13334`, freed a third time when the corpse decays (`free_obj()` -> `free_object_strings()`).

Second trigger, same cause: a disconnect during the `iedit` (`close_socket()` -> `cleanup_olc()`, `src/olc/oasis.c:138`) frees `edited->char_sdesc`, which is the live corpse's.

Verified under valgrind on `8556f9ca8` with a probe that mirrors the three calls on a `clear_object()`ed `live` with `char_sdesc = strdup("Rhiannon")` and `obj_proto = NULL`:

```c
copy_object(&edited, &live);   /* oedit.c:4035 */
copy_object(&live, &edited);   /* oedit.c:3994 */
free_object_strings(&edited);  /* oedit.c:4021 */
CuAssertStrEquals(tc, "Rhiannon", live.char_sdesc);
```

`Invalid free()` at `free_object_strings (genobj.c:483)`, block already freed by `free_object_strings` from `copy_object (genobj.c:577)`, then `Invalid read` on `live.char_sdesc`.

On master the same path frees `char_sdesc` from `free_object_strings_proto()` after reading `obj_proto[-1]`. `a0757112c` removes the out-of-bounds read and keeps the double free, and `Test_gameplay_object_editor_copy_frees_an_object_with_no_prototype` does not set `char_sdesc`, so neither sanitizer job sees it.

Fix, one line in `copy_object_strings()` after the `arcane_mark` line (the probe is clean under valgrind with it):

```c
to->char_sdesc = from->char_sdesc ? strdup(from->char_sdesc) : NULL;
```

Every copy that `copy_object_strings()` fills is later freed by `free_object_strings()` or `free_object_strings_proto()`, and both free `char_sdesc`, so the copy has to own it. Give the new test `source.char_sdesc` and `live.char_sdesc` of their own, assert `live.char_sdesc` equals the source text at a different address, and free both, so the memory-check and sanitizer jobs cover the path.
