## Cause

Two functions in `src/olc/genobj.c` wrote one whole `struct obj_data` over another and then put
back a list of the target's runtime fields: `update_all_objects()`, for every live object of a
prototype that OLC saves, and `copy_object_main()`, for the editor copies. Each list was older
than fields the struct has gained.

After an OLC save of a prototype, each live object of it

- pointed at the prototype's special abilities and spellbook. `free_obj()` frees both with the
  object, so extracting one live object freed the prototype's lists under it and under the other
  live objects;
- had lost its hash links while still on its `obj_rnum_hash` chain, and its sheath pointers,
  trap, group-loot link and pending limb slot;
- had dropped its own strings, arcane mark and restring identifier without freeing them.

The iedit commit wrote back the hash links, sheath pointers and trap the object had when the
edit began.

## What changes

`584524ec5`, handed to review:

- `overwrite_object()` is the one place that says what a target keeps when another object is
  written over it: where it is, what holds it and what it holds, its list, hash and registry
  links, its events and transfer state, its sheath pointers and trap, and the other runtime-only
  fields. `copy_object_main()` goes through it, and the iedit commit's own restore list is gone.
- `give_obj_own_copies()` is the part of `read_object()` that gives an object copies of its own of
  its prototype's arcane mark, restring identifier, spellbook and abilities.
- `index_object()` clears the slot a new prototype goes into, and `oedit_setup_existing()` clears
  its edit copy, since a copy keeps the target's runtime fields.
- Fixed in the same commit: an edit copy shared `char_sdesc` with the live object and both freed
  it (the line is also phase 3's `ddacf712f`), and a new prototype kept the event and registry
  fields of whatever its slot held.

`8e7b0b073`, review:

- `adjust_objects()` and `delete_object()` move each renumbered live object to the hash chain of
  its new rnum. They left it on the old chain, and the next `read_object()` into that bucket wrote
  into a freed object.
- Both skip objects with no prototype. `delete_object()` gave such an object a bogus rnum that
  `extract_obj()` used as an `obj_index` subscript. A notice board with no object stays NOTHING.
- `remove_obj_from_rnum_hash()` leaves a chain the object does not head alone. A mail letter or
  forged note has rnum 1 on no chain (#31), and removing it emptied that bucket.
- `delete_object()` frees the deleted prototype's strings and trigger list.

`dd9732777`, review:

- An OLC save gives each live object the new prototype's definition field by field where the
  object still held the old prototype's, and keeps what it has of its own, as a reload from a save
  would. Before, a save of a carrier prototype rewrote every generated weapon and armour in the
  game, and any save took restrings, arcane marks, scribed spellbook pages, an essence's level and
  a resized item's size. `add_object()` keeps the old prototype until the live objects are done.
- The save no longer drops a live object's script while it stays registered for random and time
  triggers, which read the object after it was freed. `overwrite_object()` keeps the target's
  script.
- A live target of `overwrite_object()` keeps its rnum, the key of its hash chain.
- A save and an iedit commit carry a change in an object's weight to its containers and carrier,
  as `obj_to_obj()` counts it.
- The save frees the old prototype's trigger list and each live object's own.
- `MAX_TEST_CASES` rises from 2048 to 4096: the suite has 2049 tests.

**Use-after-free: an OLC save orphans each live object's script while it is still scheduled**

**Location:** `src/olc/genobj.c:588` (`*to = *from;` in `overwrite_object()`), reached from `update_all_objects()`. The cleanup that should catch it is `src/olc/oedit.c:330-331`.

`script` is not on the kept list, so `update_all_objects()` sets `SCRIPT(obj)` to the prototype's NULL. `oedit_save_internally()` runs right after it with `if (SCRIPT(obj)) extract_script(&obj->script);` for each live object, and that line can never fire.

The dropped `script_data` is not just leaked:

- It stays registered with the DG random and time registries, for the trigger types it has, with `owner` = the object.
- Any trigger of it sitting in `wait` keeps its wait event. `trig_wait_event()` resumes without an owner check because "Owner teardown extracts attached scripts" (`src/dgscript/dg_scripts.c`), and after the save the owner's teardown can no longer reach this script.

Once the object is extracted:

- the next random-trigger dispatch reads `SCRIPT()` of the freed object in `dg_random_registry_resolve_owner()`;
- a waiting trigger calls `script_driver()` with the freed object as `go`.

Until then, the orphaned triggers keep running against the object beside the ones `assign_obj_triggers()` adds. The "Not in this merge request" section counts the script as a leak; it is a use-after-free.

**Repro (builder):** an object prototype with an OTRIG_RANDOM trigger (or any trigger that runs `wait`) and one loaded instance. Oedit the prototype, change anything, save. Purge or junk the instance before the next DG pulse.

ASan probe on `6a55903f5`, steps:

1. A live object from `read_object()`, with a script bound by `dg_script_bind_owner()`.
2. `add_object()` of an edit copy, then the save loop's `extract_script()` check.
3. `extract_obj()` of the live object.
4. One `PULSE_DG_SCRIPT` of `event_test_advance()`.

```
ERROR: AddressSanitizer: heap-use-after-free ... READ of size 8
    #0 dg_random_registry_resolve_owner src/dgscript/dg_handler.c:333
    #1 periodic_dg_random_event src/events/periodic_owners.c:195
freed by: free_obj src/core/db.c:7465 <- extract_obj src/core/handler.c:3127
```

**Fix:** keep the script in `overwrite_object()`. It is runtime state of the target, and the save loop's existing `extract_script()` then cancels the waits and unregisters it before `assign_obj_triggers()`:

```c
  *to = *from;
  SCRIPT(to) = kept.script;
```

Every other caller already holds NULL there: the edit copies and prototypes come from `clear_object()`, and the iedit commit extracts first. The fix also ends the preview copy's script sharing that #29 lists. With it the probe is clean.

**Hash links kept, hash key not: a live target ends up on another rnum's `obj_rnum_hash` chain**

**Location:** `src/olc/genobj.c:600` (`to->next_in_hash = kept.next_in_hash;`), with `item_number` taken from `from` at line 588.

`obj_rnum_hash` is keyed by `item_number`: `remove_obj_from_rnum_hash()` picks the bucket from it, and `obj_index[item_number].number` counts the live instance. `overwrite_object()` keeps the target's chain links but takes the source's rnum. When the target is a live object of another prototype, it stays in its old bucket, labelled with the new rnum.

The caller that does this today is #29's preview copy: `read_object()` of the carrier, then `copy_object()` of another object over it. Extracting that object while it heads its bucket runs the bucket-head branch of `remove_obj_from_rnum_hash()` on the wrong bucket. Two ways that happens: #29's proposed fix, or `delete_object()` of the other prototype.

- The other prototype's bucket loses its chain, so `get_obj_num()` stops finding the other object.
- The carrier's bucket keeps the freed object as its head, and the next `read_object()` of the carrier writes into freed memory.

**Second path:** an iedit commit after a new prototype has shifted the rnums. The edit copy's stale `item_number` is written onto the live object, which then has another prototype's vnum and is saved under it.

**Repro:** ASan probe on `6a55903f5` with two prototypes, rnum 0 and 1:

1. `player = read_object(rnum 1)`
2. `temp = read_object(rnum 0)`
3. `copy_object(temp, player)`
4. `extract_obj(temp)`
5. `read_object(rnum 0)`

```
ERROR: AddressSanitizer: heap-use-after-free ... WRITE of size 8
    #0 add_obj_to_rnum_hash src/core/db.c:5163
    #1 read_object src/core/db.c:5271
freed by: free_obj src/core/db.c:7465 <- extract_obj src/core/handler.c:3127
```

After step 4, `get_obj_num(1)` no longer returns `player`.

**Fix:** a live target keeps its rnum, as it keeps the rest of its place in the world:

```c

```

The edit copies and prototypes are not list members, so they still take the source's rnum. With the fix the probe is clean and `player` stays findable.

**Pre-existing, same overwrite: carried and container weight go out of step after a save or an iedit commit**

**Location:** `src/olc/genobj.c:88` (`update_all_objects()`). The iedit commit goes through the same `overwrite_object()`.

`obj_to_char()` and `obj_to_obj()` add an object's weight to its carrier's `IS_CARRYING_W()` and to every enclosing container's `GET_OBJ_WEIGHT()`. The matching `obj_from_*()` subtract the weight the object has at removal time. Nothing recomputes these totals for a player.

The overwrite replaces `obj_flags.weight` in place:

- A container loses the weight of its contents. Removing them later subtracts it again, so the container's weight goes negative.

- The iedit commit writes the weight snapshot taken when the edit began, so contents moved while the editor was open throw the totals off the same way.

1. Record `GET_OBJ_WEIGHT(obj)` before the overwrite.
2. Afterwards, add back the weight of `obj->contains` when the container's capacity is limited, as `obj_to_obj()` counts it.
3. Apply `new - old` to every `in_obj` ancestor, and to `IS_CARRYING_W()` of the top holder's `carried_by`.
