Closes #16

Phase 4 of `docs/ongoing-projects/object-save-fixes-and-arm-pricing.md`. Handed to review at
the tag `object-save-fixes-p4` (`0a662d23a`): three code commits, each with its test, and the
plan's record of the phase.

## Cause

`extract_char()` called `empty_bags_to_inventory()` (`src/core/handler.c`), which only unlinked
each bagged object: nothing put it in the inventory and nothing extracted it, so it stayed in
`object_list`, held by no one, after its owner left the game. It passed bag number 1 to
`obj_from_bag()` for all ten bags, so the move it reported named bag 1. The leaving save
(`objsave_save_and_extract()`) wrote the bags but extracted only the worn and carried objects.

The plan's check before the change failed: nothing kept a carried object from being dropped in
the room on a leave without a save and loaded again from the last save. `extract_char_final()`
calls `Crash_delete_crashfile()` for that, which deletes a crash save's file, but under
`OBJSAVE_DB` (always defined in `src/obj/objsave.c`) it returns at once and the rows stay. A
crash-saved carried and worn gem, then a purge: both lay in the room and both rows were still
there. So the bags could not simply follow the carried objects, and that defect is fixed first.

## What changes

`d989a8517`: once `extract_char_final()` has dropped anything in the room, it writes the
character's object save again. The character holds nothing by then, so the rows, the header and
the file all come out empty, and the next login does not bring back what the room holds. A
character that left with a rent, idle or cryo save holds nothing at that point, and its save
stands. The `Crash_delete_crashfile()` call there goes. Making that function work under
`OBJSAVE_DB` instead would also delete the crash save at every death, its other two callers,
where the character keeps all its objects (`make_pc_corpse()` moves none).
`Test_leaving_without_a_save_drops_everything_and_keeps_no_object_save` covers it.

`be819da53`, the bags:

- `extract_char_final()` takes each bagged object out of its own bag and puts it in the room, as
  it does the carried and worn ones. The move names the bag. `empty_bags_to_inventory()` goes:
  a stop in the inventory would report a move from bag to inventory, which the quest system
  counts as finding the object, and the bus dispatches it at once, to a character that is
  leaving.
- `objsave_save_and_extract()` extracts each bag's objects after the worn ones;
  `extract_obj()` already takes an object out of its bag.
- `Test_leaving_saves_keep_the_bags_and_take_them_along` replaces
  `Test_cryo_and_idle_saves_keep_what_is_in_the_bags`, which took its bagged gem out by hand: a
  cryo save leaves the bags and `object_list` empty, and a load from the saved rows puts a gem
  back in bag 1 and one in bag 3. The leave without a save now has a gem in bag 1 and one in bag
  3: both end in the room, each moved there from the bag it names.

`0980ae2dc`, found while building: `do_sort()` (sortto, sortfrom) and `do_bags()` read the bag
storage of whoever runs them, and a mobile has none (`bags` is NULL). `command_interpreter()`
lets a mobile run any command below immortal level, so either command ended the server in a
segmentation fault. Both now answer "You have no bags."
`Test_gameplay_bag_commands_refuse_a_character_without_bags` covers both.

`docs/systems/SAVE_SYSTEMS_BREAKDOWN.md` says what the leaving saves take along and what a leave
without a save does.

`0a662d23a`: the plan's record of the phase.
