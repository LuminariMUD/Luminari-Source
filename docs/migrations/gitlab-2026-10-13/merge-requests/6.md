## Description

Step S1 of the DurisMUD vessel study (`docs/ongoing-projects/vessels-ships.md`): fixes defects L4, L5, L7, L8, L9, L11, L12, and L13.

- **Gunnery:** only the owner, helm permit holders, the online owner's group, and staff may fire. A non-owner firing on another player's hull also needs the hull owner's consent. Only a permitted shot records PvP grace, once, for the actual gunner. Every shot costs lag, and hulls in port neither fire nor take fire.
- **Contacts:** `contacts`, `tactical`, and `shipfire` share one nearest-first, sight-limited list with two-letter IDs.
- **Weather:** manual sailing reads the real storm bands.
- **Crew:** a one-time hire; wages and `shipwages` are removed.
- **Shipyard:** prototypes get `for_sale` and `min_level`. The hull level gates departures (refused when it cannot be read), and a player may own at most 3 hulls (`cedit`, 1-10).
- **Bounties:** decay after a quiet day; `bounty pay` clears one for 125% at a lawful port.
- **Schema:** Phase 18 SQL, with rollback and verify files. Help is updated in `help.hlp` and the SQL component.

Review range: `vessels-s1-base..vessels-s1`. Review fixes: `vessels-s1..feat/vessels-ships`.

Verification: `make test-all` passes with DB cases on (1870 CuTest in the local CI matrix). The new `test_vessel_rules_in_game.sh` gate and the tactical, events, boarding, lookout, and narrative gates pass on the review fixes. All 33 jobs of the local CI matrix (`scripts/ci/local/run.py`) pass on the head.

Deploy: apply `vessels_phase18_schema.sql`, then re-apply the frontier package (or run `vedit set <id> forsale yes`), or the shipyard sells nothing.

Review location: src/vessels/vessels_edit.c; old line None; new line 76; head 26bd5f995210a73d9ebf74abc65504f48e269daf.

[P1] Routine departure checks run DDL on the game loop. `vessel_ship_min_level()` calls this function for every prototype-backed hull, so each `setsail`, `autopilot on`, `assignpilot`, and `setschedule` executes both `CREATE TABLE IF NOT EXISTS` and `ALTER TABLE ship_prototypes ADD COLUMN IF NOT EXISTS`. MariaDB queues `ALTER TABLE` behind a metadata lock held by another transaction (https://mariadb.com/docs/server/reference/sql-statements/transactions/metadata-locking); one blocked helm command can therefore stall the single-threaded MUD until that transaction ends. Run schema creation/migration at boot or deployment only, and make the command path a read of the already-migrated level.
