## Description

## What happens

The three object writers in `src/obj/objsave.c` store one `SpAb:` line, for the first ability of
the object's list: `objsave_save_obj_record_internal()` (rent files, player rows, house rows),
`objsave_save_obj_record_db_pet()` and `objsave_save_obj_record_db_sheath()`.

```c
specab = obj->special_abilities; /* no loop */
"SpAb: %d %d %d %d %d %d %d %s\n", ...
```

The loaders build an object's list from its prototype and put that one record on it
(`objsave_replace_special_ability()`, as of MR !23). Nothing else of the saved object's list is in
the row, so after a load:

- An object with no prototype has its first ability only.
- A change to an ability that is not the first is undone, and the prototype's version is back.
  The weapon-oil loop in `do_applyoil()` (`src/obj/act.item.c`) upgrades the first ability that
  can be upgraded, which need not be the first of the list, and a staff `iedit` can change any.
- An object whose list was emptied has its prototype's abilities again: no line is written for an
  empty list, and one path in `src/obj/act.item.c` empties the list of an object in play.

## Evidence

Run on `1d904677a` (the head of MR !23) with a prototype that has two abilities, through
`test_objsave_save_obj_record()` and `objsave_parse_objects()`:

```
emptied list:                 0 saved -> 2 loaded
second ability, level 12->20: 20 saved -> 12 loaded
```

The first case is read from the code: `create_obj()` gives no list and the row has one line.

## Fix

Store the whole list: one line per ability, and a mark that tells such a row from today's rows (a
count line before them, or a new tag). For today's rows one line means "the first ability, the
rest from the prototype"; for a new row the lines must be the whole list, an empty one included.
The loaders replace the list for a new row and keep today's handling for an old one. The pet
decoder validates the new lines; the pet save fingerprint already covers the whole list.

Tests: round trips of a two-ability object with no prototype, of a prototype-backed object with
its second ability changed, and of one with its list emptied, through the file, player, sheath and
pet paths, and an old one-line row that still loads as it does today.

Found in the review of MR !23 (work item #19). It is older than that merge request and not part
of it.
