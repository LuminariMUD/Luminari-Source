## Description

**Defect.** `do_otransform()` (`src/dgscript/dg_objcmd.c`) turns an object into another prototype by reading a fresh copy of the new prototype, copying that object over the live one with `memcpy()`, keeping eleven of the live object's fields, and extracting the fresh copy. The live object comes out of it with the fresh copy's `next_in_hash` and `prev_in_hash`, while the objects on its own rnum hash chain still link to it: after the fresh copy is unlinked and freed, the old chain runs through the live object into the other chain, and the live object's later removal from the hash edits the other chain and leaves its old neighbours pointing at freed memory, which the next walk of that chain reads. The prototype counts go the same way: the live object keeps the old rnum's count and later decrements the new rnum's (`SYSERR: Attempt to decrement object count below 0`). The live object also takes the fresh copy's event list, which the fresh copy's extraction frees.

**Fix.** Move the live object to the chain of its new rnum (`remove_obj_from_rnum_hash()`, then `add_obj_to_rnum_hash()` after the copy) and carry the count from the old rnum to the new one, as `delete_object()` and `adjust_objects()` do since `8e7b0b073`; keep the live object's events, hash links and registry state with the other kept fields, as `overwrite_object()` in `src/olc/genobj.c` does. Four world triggers use `otransform` (`lib/world/trg/`).

Seen while fixing the review findings of [MR !28](https://gitlab.com/max757/Luminari-Source/-/merge_requests/28) (#17), where `otransform` gained the sheath links in its kept list; read from the code, not changed there.
