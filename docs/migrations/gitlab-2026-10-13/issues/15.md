## Description

## Problem

`free_obj()` (`src/core/db.c`) frees an object's strings in one of two ways. An object with a
prototype goes through `free_object_strings_proto()`, which frees `arcane_mark`. An object with
no prototype (`GET_OBJ_RNUM(obj) == NOWHERE`) goes through `free_object_strings()`
(`src/olc/genobj.c`), which frees `name`, `description`, `short_description`,
`action_description`, the extra descriptions, `char_sdesc` and `restring_identifier`, but not
`arcane_mark`.

So an object with no prototype that carries an arcane mark leaks the mark when it is extracted.
The mark is set with `strdup()` when a saved record with an `AMrk` line loads
(`src/obj/objsave.c`, both parsers) and in `copy_object()` (`src/olc/genobj.c`).

## Evidence

Read from the code, not measured. The existing test
`Test_object_saves_bind_player_house_and_serialized_text` frees the mark by hand before
`extract_obj()` for this reason.

## Proposed fix

Free `arcane_mark` in `free_object_strings()`, after checking its other callers (the OLC cleanup
and the prototype teardown in `destroy_db()`) so that no path frees it twice.

Found on 2026-10-04 while writing the S13 tests (work item #13); it is not part of that work.
