## Description

Found in the live check of #4 (its item 30); still true on master `962463fa6`.

`device_spell_level()` (`src/act/act.other.c:11876`) admits any wizard or cleric list entry
regardless of its targets, so `device spells` lists and `device create` accepts entries such as
`SPELL_ENCHANT_ITEM` (`TAR_OBJ_INV`) and `SPELL_PRESERVE` (`TAR_OBJ_ROOM`). `device use` always
calls `call_magic(ch, target, NULL, ...)` (`src/act/act.other.c:12847`), so those get no object
and have no effect.

Entries that read the global `cast_arg3` misbehave too: only `do_gen_cast` sets it
(`src/magic/spell_parser.c:3402`), so `spell_minor_creation` (`src/magic/spells.c:5016`, wizard
level 1) run from a device reads the argument of whoever last used `cast`. The other readers in
`src/magic/spells.c` are `spell_control_summoned_creature`, `spell_siphon_might`,
`spell_human_potential`, `spell_mass_human_potential`, `spell_overland_flight` and
`spell_ventriloquate`; check which are reachable at device circles 1-4.

For each family, either refuse it in `device add`/`device create` and leave it out of
`device spells`, or pass the object and argument through `device use`.
