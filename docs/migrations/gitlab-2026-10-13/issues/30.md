## Description

## Problem

`add_object()` (`src/olc/genobj.c`) replaces an existing prototype and then calls
`update_all_objects()`, which writes the whole new prototype over every live object of that
prototype (`*obj = *refobj`) and puts back a list of runtime fields. The list is older than
several fields of `struct obj_data`. After the save, each live object of the prototype:

- shares the prototype's `special_abilities` list and `sbinfo` array. `read_object()` gives
  every object a copy of its own and `free_obj()` frees both with the object, so extracting one
  live object frees the prototype's list. The prototype, the other live objects and the next
  `read_object()` of that prototype then use freed memory, and a second extraction frees it
  again.
- has dropped its own `special_abilities`, `sbinfo`, `arcane_mark`, `restring_identifier`,
  restrung strings, script and `trap` without freeing them.
- has `next_in_hash` and `prev_in_hash` set to the prototype's NULL while it is still on its
  `obj_rnum_hash` chain. The chain is cut at that object, so `get_obj_num()` no longer finds
  the objects behind it, and `remove_obj_from_rnum_hash()` later empties the bucket or leaves a
  freed object on it.
- has lost `sheath_primary` and `sheath_secondary` (the sheathed weapons stay in `object_list`
  with nothing pointing to them), `next_gitem`, `limb_restore_slot` and the `rol_*` runtime
  state.

## Evidence

Run under valgrind on master `ee42019ed` on 2026-10-06, with a probe test: a prototype with
one special ability, one live object from `read_object()` that carries an arcane mark, then
`oedit_save_internally()`. After the save the live object's list pointer is the prototype's and
its mark is NULL. `extract_obj()` of the live object frees the block the prototype still points
to (an invalid read of the prototype's ability follows), and the object's own list and mark are
reported lost.

The spellbook array, the hash links, the sheath pointers and the other fields are read from the
code, not run.

## Proposed fix

Before the prototype is replaced, each live object releases what it owns, as `free_obj()` does.
After the copy it gets copies of its own of what `read_object()` copies, and every runtime-only
field is put back.

Found on 2026-10-06 while checking the callers of `free_object_strings()` for work item #15;
it is not part of that work.
