## Description

## Problem

When a command waits a pulse in the action queue, the server sends a second prompt that is
empty except for the telnet go-ahead (IAC GA), so the command's reply follows two prompts.
A client that ignores GA shows both prompts on one line.

## Current evidence

- Observed on 2026-10-02 during the vessel play test in the Luminari Web client, and in the
  transcripts of the scripted login helper (`scripts/development/dev_kohdee_login_smoke.sh`)
  from the vessel gates. It happens with any queued command, not only vessel commands.
- `make_prompt()` in `src/core/comm.c` appends IAC GA to the prompt even when the prompt text
  is empty (the branch that sets `*prompt = '\0'`), so an otherwise empty prompt is still sent.
  `src/core/comm.c` has not changed since the observation. The exact path that asks for the
  extra prompt was not traced.

## Completion criteria

- The path that produces the second prompt is identified.
- A command that waits in the action queue is followed by one prompt, or the bare go-ahead is
  shown to be intended and is documented in `docs/systems/PROTOCOL_SYSTEMS.md`.
- A test in the prompt tests (`comm_make_prompt_for_test()` exists for them) or a transcript
  check covers it.
