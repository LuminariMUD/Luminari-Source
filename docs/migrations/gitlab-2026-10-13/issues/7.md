## Description

Found in the live check of #4 (its item 28); still true on master `962463fa6`.

`device` is registered with `ACTION_STANDARD` (`src/core/interpreter.c:1494`), and the
interpreter refuses a command whose actions are unavailable with "You must wait for the required
action before trying that command." (`src/core/interpreter.c:6963`). `device use` spends the
standard action (`USE_STANDARD_ACTION(ch)` in `ACMDU(do_device)`, `src/act/act.other.c`), so
right after a use the read-only subcommands `device list`, `info`, `spells`, `usage` and
`cooldown` are refused too.

Only the acting subcommands (`use`, `create`, `add`, `repair`, `destroy`, ...) should need the
action. `is_device_cancel_command()` (`src/core/interpreter.c:6585`) already reads the subcommand
before the busy check and is a model.

## Done when

- [ ] `device list`, `info`, `spells`, `usage` and `cooldown` work without an available standard
  action; `device use` and the other acting subcommands still need it.
- [ ] A production-linked test in `unittests/CuTest/test_artificer_devices.c` that fails on the
  old code (`CUTEST_FILTER=artificer ./cutest`).
- [ ] `make -j$(nproc)`, `make test` and `make install` pass.
