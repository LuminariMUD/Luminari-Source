## Description

Player report (Voduk, level 22, room 103056, 2026-09-27): `device spells` lists 4th-level
spells for a level 20 artificer, but adding anything above 2nd level to a device fails with
"That spell is not available to artificers of your level."

## Cause

`device add` in `ACMDU(do_device)` (`src/act/act.other.c`, around line 12819) compares a class
level against a spell circle:

```c
if (spell_assignment_level >= LVL_IMMORT || spell_assignment_level > max_spell_level)
```

- `spell_assignment_level` is `MIN(min_level[CLASS_WIZARD], min_level[CLASS_CLERIC])`, a class
  level (for example lightning bolt is wizard level 5).
- `max_spell_level` is a circle cap: 4 at artificer 11+, 3 at 5+, 2 at 3+, else 1.

At artificer 11+ the cap of 4 admits class levels 1-4, which are circles 1-2. Every 3rd-circle
(class level 5) and 4th-circle (class level 7) spell is rejected, exactly as reported. Lower
artificer levels are affected the same way (at 5-10, cap 3 admits only circles 1-2).

`device create` and `device spells` are correct: both convert to a circle with
`(min_level + 1) / 2` / `compute_spells_circle()` before comparing to `max_spell_level`.

## Fix

Convert to a circle in `device add` the same way `device create` does before the cap
comparison.

The same block also skips work `device create` does: it does not store
`inv->spell_levels[]` for the added spell and does not check the per-circle budget from
`weird_science_table`. Once circles 3-4 become reachable through `add`, that lets `add`
exceed the circle limits `device create` enforces; decide in the fix whether `add` should
apply the same budget check.

## Test

Production-linked CuTest: a level 20 artificer with an existing device can `device add` a
3rd- and 4th-circle wizard spell, and a level 3 artificer cannot add a 3rd-circle spell.

## Other artificer defects (class pass, 2026-09-27)

Found in a read-through of the whole class; each was confirmed by tracing the code, not
reproduced in game. Lines are in `src/act/act.other.c` unless a file is named.

### High

1. **Stack overflow from `device create`.** `find_skill_num()` (`src/magic/spell_parser.c:509`)
   copies each word with the unbounded `any_one_arg()` into the 256-byte `first2`, and the
   device parser accepts a single word of up to 511 characters (12117-12133). A 300-character
   word skips the exact match and overruns the buffer, crashing the server.
2. **Broken state is not saved.** `broken` and `dc_penalty` are never written or read
   (`src/player/players.c` 3370-3400 save, 5273-5381 load). Breaking also sets `uses = 0`,
   so after relog a broken device comes back working, fully charged and with no penalty.
   The rename scanner's line counts (`src/player/player_rename.c` 573/597/619) must match.
3. **`device use` keeps casting after the target dies** (13064-13071). It ignores
   `call_magic()` returning -1; the potion path breaks on `<= 0`
   (`src/magic/spell_parser.c:1736`). A PvP victim moved to the start room gets hit by the
   remaining spells there.
4. **Metamagic Science on wands and staves costs 1 charge** (`src/magic/spell_parser.c`
   1585, 1670). `calculate_metamagic_charge_cost()` is only used for stored wands/staves
   (`src/obj/act.item.c` 7331, 7431), so `use wand maximized <target>` on a 1-charge wand
   works when it should need 4.
5. **Improved Metamagic Science UMD check can never fail.** It tests `umd_check < 0`, but
   `skill_check()` returns 0 on failure (`src/magic/spell_parser.c:1541`,
   `src/obj/act.item.c` 7071, 7203). Stored quaff/recite also build the DC from
   `spell_level` still at its initial 99 (7026), giving DC 317+, so fixing only the
   comparison makes it always fail.

### Medium

06. **`device create cancel` and `device repair cancel` are unreachable.** The busy
    allow-list (`src/core/interpreter.c:6866`) blocks every `device` command during creation
    or repair, and `device` has no `CMD_FEATURE_ACTIVITY_CONTROL`. The progress message
    (13960) still tells the player to type the cancel. `quit` is blocked too, for the whole build (up to 630 s).
07. **Skills pass as 1st-circle device spells.** `init_spell_levels()` gives every skill
    `min_level` 1 for all classes (`src/character/class.c:3726-3731`). `device create kick`
    uses a 1st-circle slot, and `device use` skips spell numbers `>= NUM_SPELLS`, so the
    device does nothing.
08. **Elbow Grease and Jack of All Trades never reach craft rolls.** The bonuses are added
    only in `compute_ability()` (`src/character/abilities.c:130-172`); every craft check reads
    raw ranks via `get_craft_skill_value()` -> `GET_ABILITY()`
    (`src/craft/crafting_new.c:6191`, used by `craft.c`, `crafts.c`).
09. **No starting gear for artificers.** `newbieEquipment()` has no `CLASS_ARTIFICER` case
    (`src/character/class.c:2568-2650`) and logs "Invalid class sent to newbieEquipment class!".
10. **Construct Iron Golem is unreachable.** Assigned at level 30 (`src/character/class.c:9257`)
    but the class caps at 20, so `craft create golem type iron` is always refused for
    artificers.
11. **Brilliance and Blunder cannot be obtained.** `feato(..., can_learn FALSE)`
    (`src/character/feats.c:5943`) and no race or class assigns it. The 4-spell devices and
    the explosion code below are unreachable until it is granted.

### Low

12. **Explosion skips death handling** (12990-13020). It lowers HP with
    `combat_apply_raw_damage()` and only prints "proves fatal"; the artificer or groupmate
    stays standing below 0 HP. Latent until item 11 is fixed.
13. **Explosion damage is 11d6 per non-wizard spell** (12976-12978).
    `compute_spells_circle(CLASS_WIZARD)` returns `NUM_CIRCLES + 1` for cleric-only spells.
    Latent until item 11 is fixed.
14. **Circle slots are assigned greedily in typed order** (12359-12375). With one 1st-circle
    slot left, `device create strength "mage armor"` fails but `"mage armor" strength`
    succeeds.
15. **Per-device cooldown is dead.** `cooldown_expires` is never set to a future time (only
    zeroed at 13740, 14110), so the destroy lock (12578), `device cooldown`, and the
    COOLDOWN tag in `device list` never trigger.
16. **`device info` never shows BROKEN.** It infers status from `cooldown_expires` and
    `uses` (13306) instead of reading `inv->broken`.
17. **Failed uses cost no action.** A broken-device attempt (12877) and a failed UMD
    (12950-13028) return before `USE_STANDARD_ACTION` (13074); the interpreter only checks
    availability, so the player can retry at once.
18. **Build time uses the wrong spell level** (12457-12459). It prefers the wizard level
    even when the lower cleric level was assigned: `strength` takes 90 s instead of 30 s.
19. **"Available device slots" is inflated** (12057-12064). It adds every existing device
    that is off cooldown, so a level 1 artificer with a full slot is told 1 is available.
20. **Extra spells are silently dropped** (12101). `device create a b c d` without
    Brilliance and Blunder builds a 3-spell device with no warning.
21. **Destroy warning says 30 minutes** (12611) but the code sets 20 (12653).
22. **Premade artificer wastes feat picks** (`src/character/premadebuilds.c:2295-2303`). It
    buys Craft Magical Arms and Armor at 1 and Craft Wonderous Item at 1 (human) and 3,
    which the class grants free at 5 and 4.
23. **Artificer Item Creation does nothing.** Granted at level 2
    (`src/character/class.c:9249`) but never checked anywhere in `src/`.
24. **No artificer class help.** `class-artificer` and `artificer-class` point to the
    CLASS-ROSTER entry in both `help.hlp` (6415) and the help DB.
25. **Device table read past its end at artificer level 21+** (12047,
    `weird_science_table[artificer_level - 1]`). Only staff `advance` can push the class
    level past 20.

## Practical check: device creation at level 1 (live, dev server, 2026-09-27)

Created a fresh human premade artificer (Gizmotest) on the dev server and ran the device loop.

**Is it essential?** Yes. The artificer has no spell progression (`classo` spell progression
"none"; score shows MgcLvl 0). Weird Science devices are the class's only access to spells,
and the feat is granted at level 1.

**Can they build one early?** Yes. At level 1, `device create "mage armor"` built a device in
30 s with no materials or gold. `device use 1` applied mage armor, and the single charge
recharged about 30 s later out of combat (`check_device_one()`, `src/core/limits.c:2236`).
Level 1 allows one 1st-circle device (`weird_science_table`); 2nd circle opens at 3, 3rd at
5, 4th at 11. Items 6, 9, 22 and 24 above were reproduced live.

New findings from this check:

26. **The device help describes a different mechanic.** The `DEVICES` entry (`device`,
    `device-create`, `artificer-devices`; `help.hlp` 9807 and the help DB) gives
    `device create <device-type>` and talks about components, blueprints, infusions and
    automations. The real syntax is `device create <spell> [spell2] [spell3]` with quoted
    multi-word names, and none of the other subcommands are documented. Its "See also:
    ARTIFICER" leads to the class roster (item 24). A player guessing `create device` gets
    "Sorry, but you cannot do that here!".
27. **No starting weapon or armor (item 9, seen live).** After creation the artificer wears
    nothing and carries only a quiver and a backpack, so at level 1 its only attack is one
    device charge per fight.
28. **Information subcommands need a free standard action.** The whole `device` command is
    `ACTION_STANDARD` (`src/core/interpreter.c:1494`), so right after `device use`,
    `device list`, `device usage` and `device cooldown` were refused with "You must wait
    for the required action before trying that command."
29. **Weird Science text contradicts the mechanic.** The feat says devices "are temporary
    and can be used a limited number of times per day" (`src/character/feats.c:5864`).
    Devices are permanent (`duration = 24` is stored but never read) and recharge one use
    per tick out of combat.
30. **Spells that need an object or argument do nothing from a device.** `device spells`
    lists and `device create` accepts spells such as enchant item (`TAR_OBJ_INV`) and
    preserve (`TAR_OBJ_ROOM`), but `device use` always passes a NULL object, so they have no
    effect. Minor creation reads the global `cast_arg3`, which only `do_gen_cast` sets
    (`src/magic/spell_parser.c:3390`), so a device uses whatever argument the last player
    to type `cast` supplied.

### Comment 3913323760

Fixed on branch `4-artificer-device-add-rejects-3rd-and-4th-circle-spells`, MR !5. All 26 items are addressed, including the reported `device add` bug.

Design decisions (items the report left open):

- `device add` charges the same per-circle slot budget as `device create`.
- Item 10: Construct Stone Golem moves to artificer 15 and Construct Iron Golem to 20.
- Item 11: Brilliance and Blunder is a gnome racial next to Gnomish Tinkering. Existing gnomes get it only on respec.

Help is updated in the dev help DB and `help.hlp`. Production help is not synced yet.
