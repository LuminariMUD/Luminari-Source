## Description

## Problem

S11 (#10) made `cargobuy` and `cargosell` save the captain's gold with `save_char_checked()` and undo the trade when that save fails. The other vessel commands that take or pay gold still write the ship's side to MariaDB at once and move the gold in memory only (`award_gold()`). The gold reaches the player file with the next per-minute save (the persistence step in `src/core/comm.c`). A crash before that save splits the two stores:

- A purchase keeps what was bought and gives the gold back.
- A payout takes the item or the freight and never pays.

Most of these commands also do not check the ship-side save: `vessel_db_save_weapons()`, `vessel_db_save_runtime()` and `vessel_db_save_cargo()` return a result that is dropped, and `vessel_db_save_crew()` and `vessel_db_save_extras()` return none. A refused write goes unreported.

Not part of this: the passenger fare, the insurance and merchant-consequence deliveries, and cargo trades already save the gold checked; freight acceptance and dock fees do too and become two-phase with #12. The land and sea transport fare (`enter_transport_paid()`, `transport.c:522`) keeps the fare and the journey in the same player file, so nothing splits.

## Proposed fix

S11's level, in the shape the passenger fare already has (`vessel_collect_passenger_fare()`: debit, `save_char_checked()`, restore on failure), through one shared helper:

- Both stores are written and checked inside the command, and a failure of either is undone and reported, so only a crash between the two writes of one command can split them.
- A purchase whose gold cannot be saved is refused; a purchase whose ship-side write fails is refunded.
- A payout whose gold cannot be saved puts the item or the freight back.
- DB-backed CuTest cases per command family for a failed gold save and a refused ship-side write.

Not #12's two-phase settlement record: each of these commands would need its own stored undo (delete a hull, strip a weapon, dismiss a crew), and the window left after a checked save (a failed save, a failed undo, then a crash) is the one #12 closes for cargo, freight and dock fees.
