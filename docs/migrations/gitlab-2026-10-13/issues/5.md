## Description

## Problem

A character receives racial feats only from `process_race_level_feats()`
(`src/character/class.c:3086`), which `advance_level()` runs for the level just reached. A feat
added to an existing race therefore reaches only characters created or respecced afterwards (a
respec reruns `do_start()`). Saved characters silently lack mechanics their race now provides.

Evidence on master `962463fa6`, counted from the development player files (`lib/plrfiles/*/*.plr`,
characters whose `Feat:` block records any feats):

| Race | Feat (assigned at level 1 in `src/character/race.c`) | Added by | Characters missing it |
| -- | -- | -- | -- |
| Half-Troll | Bodyslam (`FEAT_BODYSLAM`) | `0831ef644` (2026-09-12), which turned the race check into a feat check | 85 of 85 |
| Crystal Dwarf | Stability (`FEAT_STABILITY`) | `0831ef644` | 31 of 33 |
| Trelux | Psionic Resistance (`FEAT_PSIONIC_RESISTANCE`) | the Duris races work (#2) | 20 of 20 |
| Gnome | Brilliance and Blunder (`FEAT_BRILLIANCE_AND_BLUNDER`) | #4 (`e4946d92e`) | 215 of 215 |

So old Half-Trolls lost the bodyslam skill, old Crystal Dwarves their knockdown resistance, and no
existing gnome can build a four-spell artificer device. `racefix` cannot help: it reads the
deprecated `level_feats[][]` array in `src/character/class.c:2072`, which has none of these rows.

Because of this gap, two damage checks in `src/combat/fight.c` keep a race test beside the feat:
`GET_RACE(ch) == RACE_TRELUX || HAS_FEAT(ch, FEAT_PSIONIC_RESISTANCE)` (line 3915) and
`IS_LICH(ch) || HAS_FEAT(ch, FEAT_COLD_IMMUNITY)` (line 3429). `docs/systems/GAME_MECHANICS_SYSTEMS.md`
("Racial Innate Feats and Spell-Like Abilities") documents that workaround.

## Fix

When a character enters the game, grant each single-rank racial feat that its real race assigns
at or below its level and that it does not hold, through the same code the level-up path uses.

1. Shared grant: move the per-assignment body of `process_race_level_feats()` (special handling
   via `special_handling_level_feats()` or the "[race] You have gained/improved" message, then
   the rank increment and the `FEAT_DAMAGE_REDUCTION` update) into one static helper, so a
   repaired feat behaves exactly like a level-up grant.
2. Repair: add `grant_missing_race_feats()` beside it, declared in `src/character/class.h`. Skip
   NPCs and invalid races. Walk `race_list[GET_REAL_RACE(ch)].featassign_list` (the real race,
   as the level-up path does, so a disguise or wild shape changes nothing) and grant each
   assignment whose `level_received` is at most `GET_LEVEL(ch)`, whose feat has `can_stack`
   false in `feat_list[]`, and whose `HAS_REAL_FEAT()` is zero (gear granting the feat must not
   hide the gap). Log character, race and feat for each grant; return the number granted.
3. Hook: call it in `enter_player_game()` (`src/core/interpreter.c:7695`) right after the
   class-spell top-up ("make sure we assign any new spells"). Menu login, copyover recovery
   (`src/core/comm.c`) and description-completion entry (`src/character/char_descs.c`) all pass
   through there. A new character enters at level 0 and gets nothing until `do_start()` runs.
   The next save persists the feat; a login before that save repeats the same grant.

Stackable (multi-rank) racial feats stay out: a saved rank does not show which ranks came from
the race and which from class or study, so a top-up could over- or under-grant. Current racial
grants of stackable feats: Armor Skin, Damage Reduction, Enhanced Spell Damage, Fast Casting,
Fast Healing, Fast Movement, Slow Casting. No migration script, `racefix` change or new command
is needed.

Once the repair lands, drop the Trelux race test from the psionic resistance check. All 14
development Liches already hold Cold Immunity; drop `IS_LICH()` from the cold check too unless
production data shows otherwise (Lich electric immunity stays a race check).

- [ ] Tests in `unittests/CuTest/test_racial_innate_feats.c`: a saved Half-Troll without
  Bodyslam and a Crystal Dwarf without Stability each gain it once and a second call grants
  nothing; a held feat keeps its rank; an assignment above the character's level is skipped; a
  stackable racial feat (Armor Skin on a Half-Ogre) is not topped up; the real race is read
  while a disguise race is set; an NPC is untouched.

  feat with `featset <name> '<feat>' -1` (for example Bodyslam on a Half-Troll), reconnect, see
  the "[race] You have gained" line, use the feat, find it in the player file after the next
  save; repeat through a copyover.
- [ ] The two race tests in `compute_damtype_reduction()` are removed or their retention is
  justified in the code.
- [ ] `docs/systems/GAME_MECHANICS_SYSTEMS.md` (racial innate section) and
  `docs/guides/ADDING_NEW_RACE_GUIDE.md` (racial feats) say that a single-rank feat added to an
  existing race reaches saved characters at their next login, while a stackable grant still
  reaches only new or respecced characters.
- [ ] `make -j$(nproc)`, `make test` and `make install` pass.

Rollout note: production picks the repair up at the next restart, which needs its own approval;
the log lines count the repaired characters. A rollback leaves granted feats in place, which is
what those characters should hold.
