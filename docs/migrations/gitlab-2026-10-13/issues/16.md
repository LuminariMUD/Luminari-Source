## Description

**Defect.** When a character leaves the game, what it had sorted into its bags stays in memory with no holder.

`extract_char()` calls `empty_bags_to_inventory()` (`src/core/handler.c`). Despite its name, that function only unlinks each bagged object with `obj_from_bag()`: no `obj_to_char()` follows, and nothing extracts the object. The objects stay in `object_list` for the life of the process.

**Effect.** Memory only. Every quit, idle-out or rent of a character with bagged objects leaks them, and anything that walks `object_list` goes on visiting them. Nothing is lost from the save: the leaving save writes the bags first (`Crash_save_bags()`), and the next login loads them from their rows.

**Also in that function.** It passes bag number 1 to `obj_from_bag()` for all ten bags, so the domain transfer record names the wrong bag for bags 2 to 10.

**Fix.** Extract the bagged objects where the leaving save extracts the worn and carried ones (`objsave_save_and_extract()` in `src/obj/objsave.c`), and decide what `extract_char()` should do with them on the paths that do not save first.

Found while fixing the review of MR !20 (S13); read from the code, not measured. Not changed there.
