## Problem

Small stale or dead items noted while the vessel steps were built and reviewed. None changes
behavior; each misleads a reader.

Code:

1. `route_save()` in `src/vessels/vessels_autopilot.c` (declared in `src/vessels/vessels.h`)
   has no callers.
2. The comment on `save_all_vessels()` in `src/vessels/vessels_db.c` says "Should be called at
   shutdown and periodically during auto-save". It is called at shutdown and at copyover only,
   and the checked-purchase design relies on that (`docs/systems/VESSEL_SYSTEM.md`: "nothing
   saves the fleet periodically").
3. `vesseldebug balance` prints "holding the healthier beam at 6-9 rooms"
   (`src/vessels/vessels_balance.c`). The harness captain holds 7.5 rooms
   (`VESSEL_BALANCE_DUEL_HOLD`); the 6-9 band was replaced.
4. `GET_VESSEL_INSURANCE_CLAIM()` and `GET_VESSEL_MERCHANT_CONSEQUENCE()` in
   `src/core/utils.h` do not parenthesize their argument; `GET_VESSEL_SETTLEMENT()` beside
   them does.
5. Two `INSERT` statements in `src/vessels/vessels_autopilot.c` (`ship_waypoints`,
   `ship_routes`) are still formatted SQL, not prepared statements.

SQL comments:

6. `sql/components/vessels_phase25_schema.sql` describes `player_id`, and
   `vessels_phase24_schema.sql` describes `creator_id`, as `player_data.player_idnum`. The code
   stores the player-file ID (`GET_IDNUM()`), and `VESSEL_SYSTEM.md` calls
   `player_data.player_idnum` an unrelated key. Confirm and correct the comments.

Documents:

7. The size of `struct greyhawk_ship_data` is stated as 2,672 bytes in `VESSEL_SYSTEM.md`
   (three places), 5,120 in the same document's tier table and in
   `docs/testing/VESSEL_BENCHMARKS.md`, and 5,104 in `docs/development/CONSIDERATIONS.md` and
   `docs/adr/0001-unified-vessel-system.md`. The built object reports 2,712
   (`gdb -batch -ex 'print sizeof(struct greyhawk_ship_data)' src/vessels/vessels_movement.o`
   on master `d5cd6a735`).
8. `docs/testing/VESSEL_SYSTEM_TESTING.md` ("Mechanical Balance Diagnostic") says the balance
   report "lists crew payroll" (crew wages were removed) and records only the 2026-08-02 run
   as the latest balance result.

## Completion criteria

- Items 1-5 corrected or removed, with the build, `make test-all`, and the SQL interpolation
  baseline passing.
- Item 6 confirmed against the code and the comments corrected in the SQL and, if it carries
  the same text, the boot DDL.
- Items 7-8: one measured structure size in every document that states it, and the balance
  section describing the current report.
