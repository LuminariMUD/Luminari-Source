PERFMON

Usage:
  perfmon all
  perfmon summ
  perfmon prof
  perfmon mem
  perfmon csv
  perfmon sect <section>
  perfmon reset

The perfmon command reports the server's bounded performance and memory telemetry.
It is available to implementors (LVL_IMPL). Monitoring is always active; there is
no runtime perfconfig command or sampling-mode switch.

Commands:
  all    Show utilization history, cumulative named sections, game-loop
         telemetry, memory dashboard, event callback profiles, and database queries.
  summ   Show pulse, second, minute, and hour utilization history.
  prof   Show cumulative named sections, game-loop telemetry, top event
         callbacks, and database queries.
  mem    Show memory dashboard: OS virtual/resident memory, anonymous RSS,
         heap allocator breakdown, rolling growth rates, and live entity inventory.
  csv    Show sampled section data followed by cumulative game-loop counters,
         memory telemetry, event callback rows, and database queries.
  sect   Show one named profiling section.
  reset  Start a new measurement window for performance, memory, event, extraction,
         catch-up, vessel-message, and database-query counters.

The automatic startup window begins after world boot and copyover recovery. Normal
world-load allocation and boot queries are therefore part of the baseline, not
reported as live memory growth or operational database traffic.

Game-loop fields:
  Event queue calls              event_process() invocations
  callbacks                      due callbacks executed
  created                        callbacks created during event processing
  depth=initial->latest          queue depth across the report interval
  max_before / max_after         peak queue depths around event processing
  Extractions processed          characters finalized from the pending list
  Catch-up requested_missed      pulses requested from wall-clock delay
  replayed_missed                extra heartbeats actually executed
  remaining_backlog              requested pulses discarded on that pass
  budget_exhausted               passes stopped by the 100 ms replay budget

Event callback rows are the top 16 identities by total callback time. Compare
calls with average_usec: a high total and modest average usually means excess
callback volume, while a large maximum with few calls points to one expensive
callback. The registry status reports registered identities out of its fixed
512-entry capacity and counts any unregistered overflow calls.

The game loop always executes the current heartbeat. Extra heartbeats run only
while the batch remains within one normal 100 ms outer-loop budget. Unreplayed
time is discarded so the server returns to socket and command processing.
Pulse-based casting, combat rounds, cooldowns, spell preparation, and vessel
schedules keep their logical order but run later in wall-clock time during
overload.

Automatic PERFMON high-water reports are rate limited by severity. Catch-up
log messages summarize at most one five-second window, while perfmon counters
still record every slow pass.
