## #230: loaders that spin on a truncated player file

`get_line()` returns 0 at end of file and leaves its buffer alone, so a `do { get_line(); ... } while (sentinel)` loop spins forever when the file ends inside the list.

- Every list loader in `src/player/players.c` gets the shape #229 gave the feat point loaders:
  `while (get_line(fl, line) && strict_sscanf(line, fmt, ...) == <fields> && <not sentinel>)`.
  Field counts follow what `save_char()` writes (terminator `-1`, `-1 -1`, `0 0`, `0 0 0`,
  `-1 -1 -1`). The `Pryg`/`Prgm`/`Pryd`/`Pryt`/`Prdm` loaders keep `counter < MAX_MEM` first,
  because `Pryg:` has no terminator and must not eat the next tag.
- Every index is bounded against its array: the running index of `Mrcy`, `Clty`, `FDQs`, `Disc`,
  `Judg`, `Bomb`, `CfMt`, `Mote` (the eight that overran), and the index read from the file
  everywhere else (`CLvl`, `Ward`, `SpAb`, `CrAf`, `CrMo`, `CrMa`, `SklF`, `Skil`, `Feat`, evolutions,
  abilities, prayer arrays), as `load_class_feat_points()` does.
- Same defect outside the `load_*` list shape: the `Todo` loop in `load_char()`, the old-format
  `Intr` loop (`while (1)`), the four spell-preparation loaders in `src/magic/spell_prep.c` (a
  malformed or stale line `continue`s without counting, so they spin), and the single-line
  readers that parse an uninitialized buffer when the file ends right after the tag (`PTog`,
  `CLoc`, `Dvis`, `Alis`).
- A player file cut off inside a string (`Desc`, `BGrd`, `Bond`, `Flaw`, `Goal`, `Idel`, `Pers`)
  called `exit(1)` from `fread_string()`, ending the game for everyone. Those tags now read with
  `fread_player_string()` (`src/core/db.c`), which logs and returns NULL at the end of the file;
  world files keep the fatal version. The log names the player file (it used an uninitialized
  buffer).
- Tests (`unittests/CuTest/test_craft_training.c`, beside the #229 test and its fixture):
  `Test_load_char_returns_for_every_cut_off_list` feeds every list and string tag a file cut off
  after one entry through `load_char()` (hangs on the old code);
  `Test_load_char_keeps_long_lists_inside_their_arrays` loads intact lists longer than their
  arrays (old code overwrote the cruelties with mercies).

## #227: perk toggles, score width, chokers

1. Toggle storage covers every perk: `ubyte perk_toggles[PERK_TOGGLE_BYTES]`,
   `PERK_TOGGLE_BYTES (NUM_PERKS + 7) / 8`; `is_perk_toggled_on()`/`set_perk_toggle()` accept any
   id below `NUM_PERKS`. The player file stores the ids that are on, `PTg2: 417 1227`, so the line
   does not grow with `NUM_PERKS` and has no signed-byte formatting. A legacy `PTog:` line is
   ignored: no bit could ever be set, because every toggleable perk id is above 255. Its loader
   also read the next line (always `PKil:`) as the bitfield, so Perfect Kill state was never
   restored; it is now. A file without `PTg2:` gets the purchase default (on) for each owned
   toggleable perk, which restores the default the old storage dropped and matches the "toggled
   ON" message players were shown.
2. `score_display_width` is `ubyte`; `do_skore()` and `scoreconfig` drop the `unsigned char`
   read-back. The five score preferences are saved in one `ScPr:` line (width, theme, density,
   template, section order) and range-checked on load; load starts from the defaults. A file
   without `ScPr:` but with `PRF_SCORE_WIDE` loads width 120 (160 was never saved).
3. `AFFECT_MENZO_CHOKERS` (1345, after `ABILITY_SUMMON_HORDE`; 1212 is taken) replaces
   `AFF_MENZOCHOKER` as the affect's spell number, registered with `affecto()`. Old saved affects
   keep their tag; the affect lasts 5 ticks, so no migration.
4. Tests: `Test_perk_toggles_reach_every_perk_that_uses_one` (`test_perk_definitions.c`: every
   toggleable perk, the buy default, Defensive Stance, the alchemist commands),
   `Test_save_char_keeps_perk_toggles_and_score_preferences` and
   `Test_load_char_restores_what_old_perk_and_score_lines_lost` (`test_craft_training.c`),
   `Test_spec_menzo_chokers_leave_iron_guts_alone` (`test_spec_mechanics.c`). All fail on the old
   code.
